# Fotufilm upstream review — 12 October 2026

Inspected GitHub main at `59d43471dbef45c85ae442e507a291fdebfb2ec5`,
14 commits ahead of our `f602857a031a6a9c9b0966284ff989eb3046c323` pin.
Latest published release is v1.12. This node update retains the v1.11 runtime,
its checksum and the additive float-memory ABI. No new engine binary is implied.

Relevant upstream changes:

- [Grain block seam fix (#258)](https://github.com/DhaliwalX/fotufilm-engine/pull/258).
  Changes tile blocks from 64 to 128 texels and cross-fades at edges, including
  variance normalization and revised grain preparation. This directly addresses
  a possible visible grid when zooming. It is not evidence that every artifact
  in an LTX result came from grain. It changes generated pixels and needs a native
  rebuild; swapping only a JSON profile cannot apply this fix.
- [Layered Transport (#260)](https://github.com/DhaliwalX/fotufilm-engine/pull/260),
  [browser preparation (#264)](https://github.com/DhaliwalX/fotufilm-engine/pull/264)
  and [uniform-field checks (#266)](https://github.com/DhaliwalX/fotufilm-engine/pull/266).
  Expand the light-transport model and stock data. Useful future advanced film
  controls; they are rendering changes, not a demonstrated fix for WAN latency.
- [Receiver bands (#263)](https://github.com/DhaliwalX/fotufilm-engine/pull/263)
  and [slides (#265)](https://github.com/DhaliwalX/fotufilm-engine/pull/265).
  Expand Digital Reference color reading. Keep these behind a deliberate engine
  migration with existing SDR and above-white float fixtures.
- [Window storage fix (#270)](https://github.com/DhaliwalX/fotufilm-engine/pull/270).
  Stores stages per row-window, including stages gated off. Review the applicable
  AOT path when rebasing our CUDA build; do not assume this is active in our pin.
- New borders, negative-scan documents, roll balancing and RGB trichromatic
  scanning mainly serve photography/scanning. They do not help our current
  AI-video interaction loop enough to expose them in Studio.

Next engine migration: rebase `prepare_float_engine.py` on one exact revision;
review configuration layout, AOT variant generation and host interface; rebuild
on Linux remotely with the float entry point; run negative/above-white input,
all advertised film/print, grain-seed, cold/warm latency and export fixtures;
then publish a new checksum-pinned runtime. Keep old engine/recipe provenance
readable. Never silently label a new rendering model as the previous engine.

The Osmo-derived interaction upgrade is independent of this migration. It copies
no Osmo shaders, tables or presets. Research: workshop
`research/osmo-2026-10-12/report.md` and `handoff.md`.
